Extend the existing feature/service/core module for its responsibility. New persistence behavior belongs in the domain interface and appropriate adapters. Add shared entities to `src/core/types/index.ts`; keep framework/device calls out of deterministic math. Check callers when changing shared helpers or barrel exports.

Smart Warmup is an opt-in `SETTINGS_KEYS.SMART_WARMUP` preference within the Automated Warm-Up Sets card in `SettingsScreen`; assessment and generation modes remain independently configurable. `ActiveLoggerScreen` refreshes it on tab activation and gates last-warmup assessments; `WarmupAssessmentModal` previews the same `calculateWarmupAutoregulation` calculation used by `ActiveSessionService.applyWarmupAutoregulation`. Maintaining preserves remaining loads; rounded suggestions report the actual change and remain within the adjustment limits. Manual warm-ups use Add Set and the set-type tag; there is no per-exercise warm-up generation button. Logger equipment and link/unlink, swap, and pain actions share a wrapping row. Each template exercise shows its shared preview prescription (load, sets, rep range, and effort) above the logging inputs. Superset link/unlink updates existing set rows in place to preserve rail order when set numbers tie. `src/core/exerciseGroups.ts.normalizeExerciseGroups` clears singleton group IDs in generated templates, previews, active-session reads, program editing and history labels; group membership counts distinct exercises. The active logger has no progression accept/dismiss banner. `captureWorkoutProgression` saves earned next-workout load increases in `training_progression_summary_<workoutId>` before block evolution; `SessionDetailModal` displays that immutable summary. Rule-earned loads take precedence over estimated starting loads while pain/recovery overrides remain in force.

The logger does not display mood-transition announcements. `transitionWave.ts` remains a legacy pure helper; live evolution uses mood nudges on actual next-block prescriptions, not cross-fade metadata. `ExerciseDetailScreen` exposes independent anchor and strength-main controls through `training_exercise_controls` settings; likes/dislikes remain in the preference repository. The logger shows the pain prompt only on the first return exposure, records a final working-set effort rating, and automatically completes the block review. `WorkoutTabRouter` retries unprocessed completed-session snapshots on return to preflight.

`SetRowComponent` uses `SwipeToDeleteSet` to reveal an explicit Delete action with a left swipe; vertical scrolling remains available. For prescriptions with an RPE/RIR target, completing an unrated working set prompts for actual effort and leaves the set open; pending input counts, warm-ups are exempt, and automatic ghost completion cannot fill in historical effort. Its compact load column omits the per-row dumbbell multiplier, and unilateral L/R inputs use a wider paired column. `resolveNextSupersetExercise` only advances to exercises with unfinished sets. Automatic warm-up eligibility is shared by template startup and in-session exercise addition through `shouldGenerateWarmups`; shortening a later warm-up requires completed working sets (or explicitly supplied warmed muscle groups), not planned sets. Gesture regressions live in logger `__tests__/swipeToDeleteSet.test.ts`.

- Validation configuration: `mobile/package.json`, `mobile/jest.config.js`, `mobile/tsconfig.json`, `companion/pyproject.toml`. [VALIDATION.md](VALIDATION.md) gives commands and scope rules.
